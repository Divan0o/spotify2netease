# 网易云匹配与保存

读取 scripts/netease.py 的实际 CLI 契约；当前适配 ncm-cli 0.1.7。版本或结构变化时先读相应 --help 和只读结果，再修改适配；不要添加不支持的 --userInput。不需要播放器、队列或 mpv。

安装与配置引导统一在[启动前依赖预检](setup.md)处理。若 ncm-cli 在批次执行中途失效，保留批次并回到该预检；`doctor` 再次返回 `ready: true` 后才恢复 search/export。

## 匹配

`workflow.py search --batch ID` 在推荐模式仅查询 selected 曲目，在存满模式查询 accepted 候选；按“主艺人 歌名”、再歌名最多两次搜索，缓存结果与失败，恢复不重复请求。推荐模式先select再search，未选中不预查。仅保留 ID、作者、曲名、专辑、时长；命令使用参数数组，不经 shell 展开。

自动匹配要求完整艺人集合、规范化曲名、版本一致且时长差 ≤1000ms，优先同专辑。未命中时不能取第一条、用翻唱替换或忽略混音。`needs_review` 查看缓存后核对艺人别名、合作艺人、专辑和时长，用：

```text
W resolve --batch ID --uri SPOTIFY_URI --ncm-id 缓存中真实ID --reason "匹配证据"
W resolve --batch ID --uri SPOTIFY_URI --reason "未能确认：具体原因"
```

不传 ncm-id 表示 unmatched，不代表网易云全站绝对不存在。ID 必须来自该曲已缓存的搜索结果。推荐数量模式保留缺失项并报告；存满模式继续寻找新 Spotify 合格候选，不以网易云另找歌曲代替上游。

## 写入与对账

达到推荐额定数且所有选中曲目匹配决定明确后执行 export。零匹配不建空单；同名不覆盖。记录账户和创建前 ID 集合、确定唯一新名称、持久保存 creating 后才发创建请求；拿到 ID 立即保存。创建超时恢复时先查账，只有唯一新匹配歌单才继续，不盲建第二个。

恢复先检查账户，分页读取歌单，只添加缺失 ID，每批最多50首。添加失败先读回，最多重试仍缺失 ID 一次；读回失败或请求总量超限停止写入并保留错误。所有调用检查 JSON 业务码，不以进程退出0代替成功。解锁后仍不能重绑已开始写入的匹配结果。

只比较歌曲 ID 集合，不比较曲序、不重排。verified 表示本批匹配目标都已读回，不表示推荐 N 首全部匹配：9个匹配全部保存时仍报告9/N。成功数取 confirmed_ids；unmatched、missing_ids、未核实各自报告。只有服务返回的数字 originalId 可生成网易云网页链接；接口操作仍用加密 id。
